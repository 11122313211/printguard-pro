# PrintGuard Pro 架构判别报告与底层优化方案

> 评估日期：2026-10-25 · 评估范围：`E:\包装印刷工作台` 全部源码（约 14,021 行 / 605 KB）
> 本报告第 1-4 章为判别与方案；第 5 章标注本次实际落地的范围。

---

## 1. 总体判别

**项目形态**：零构建纯前端单页应用（SPA）。无 package.json、无框架、无打包器，双击 `index.html` 即可运行。样式依赖 Tailwind Play CDN，3D 依赖 Three.js r128（cdnjs/jsdelivr CDN），业务引擎为 6 个本地 UMD 模块（浏览器挂 `window` + Node `module.exports` 双端兼容）。

| 文件 | 行数 | 职责 |
|---|---|---|
| index.html | 6,993 | 全部 UI 骨架 + 约 5,520 行应用脚本（状态、画布、3D、面板交互） |
| module_dxf_parser.js | 2,089 | AutoCAD/ArtiosCAD DXF 刀模解析、图层语义分类、SVG 导出 |
| module_new_boxes.js | 1,589 | FEFCO 0427 / 天地盖参数化盒型、3D 结构与运动学 |
| module_ciede2000.js | 1,390 | 色彩科学库（ICC 转换、CIEDE2000 ΔE00，Sharma 34 组向量验证） |
| module_barcode_bwr.js | 1,284 | EAN-13 / Code128 条码引擎 + BWR 条宽补偿 + GS1 静区核验 |
| module_caliper_kerf.js | 462 | 数显卡尺 + 模切刀缝 / CITO 压痕工艺计算 |
| module_ink_estimator.js | 214 | 32 墨区 CIP3 耗墨量测算 |

**分层判别（两面性极强）**：

- **引擎层：工程化程度高**。6 个模块职责单一、零 UI 耦合、均内置 Node 自测套件（条码 41 项、DXF 79 项、色差 34 组向量、盒型 42 项断言，失败即 `process.exit(1)`），可直接 `node module_xxx.js` 回归。工业标准引用（ISO 12647-2、GWG、FEFCO、GS1、FOGRA39）密集且准确。
- **应用层：单体巨石**。348KB 的 index.html 里 UI 与交互逻辑完全纠缠：713 处内联 Tailwind 类、61 处 JS 中硬编码 `className` 整串替换、卡片样式类串复制粘贴 15 次、工具提示气泡逐字重复 8 次、20+ 个 `!important` 对抗优先级、10 处内联 `onclick` 与 113 处 `addEventListener` 混用。任何视觉改动都需要在 HTML 与 JS 双侧多处同步，极易漂移。

**一句话结论**：这是一个「引擎一流、底盘裸奔」的应用——业务算法可对标专业印前软件，但应用底座（持久化、离线、容错、可维护的样式系统）几乎完全缺失，且对 CDN 有硬依赖。

## 2. 底层缺失清单（现状 → 影响 → 方案 → 优先级）

### 2.1 无任何持久化 🔴 P0 →【本次实现】
- **现状**：全项目 0 处 localStorage / IndexedDB / File System Access；所有状态仅在内存 `state` 对象（index.html:1475），刷新即全部丢失。数据出口仅有三类浏览器下载（预检报告 JSON / DXF+SVG 刀模 / 3D PNG）。
- **影响**：作为"工作台"却无法保存工作；用户上传的设计稿、调好的盒型参数、DXF 刀模在误关标签页后不可恢复；无法管理多个订单/项目。
- **方案**：IndexedDB 项目快照（含附件原稿），file:// 协议下降级 localStorage；自动保存（Proxy 拦截 state 写入 + 防抖落盘 + beforeunload 兜底）；项目管理面板（载入/重命名/删除/缩略图）；`.printguard` 工程文件导出/导入。**详见第 5 章。**

### 2.2 无离线能力 🔴 P0 →【路线图】
- **现状**：Tailwind 走 `cdn.tailwindcss.com`（官方明示不可用于生产），Three.js r128（2021 年版）走 cdnjs/jsdelivr；本地只有 6 个引擎模块。README 宣称"双击即可运行"，实际断网时整页无样式、3D 瘫痪。
- **影响**：印刷车间网络环境不可控，断网即整个工作台不可用；Play CDN 每次加载都在浏览器里跑 JIT 编译，首屏慢且行为随官方版本漂移。
- **方案（建议分两步）**：
  1. 低成本：下载 three.min.js / OrbitControls.js 到 `vendor/`，`<script>` 改本地引用；用一次性脚本把 Play CDN 生成的 CSS 快照固化为 `css/tailwind-snapshot.css`（或逐步迁移到 design-system.css 手写组件类，本次已建立该层）。
  2. 彻底：加 `<link rel="manifest">` + Service Worker 缓存，成为可安装 PWA。
- **未实施原因**：用户选定本次范围仅持久化；此列为路线图首位。

### 2.3 无全局错误防护 🟠 P1 →【基础兜底已实现 / 关键路径降级仍留路线图】
- **现状**：全文件仅 8 处 try-catch；无 window.onerror / unhandledrejection 钩子。Three.js 初始化失败（CDN 抖动/ WebGL 不可用）会直接抛异常中断后续 init 链。
- **影响**：任一环节异常即静默白屏或功能半瘫，用户无感知、无自愈。
- **方案**：`window.addEventListener('error'/'unhandledrejection')` 兜底 → 复用现有 showToast 上报；`init3DViewport` / 画布重绘等关键路径包 try-catch，失败时降级（隐藏 PiP、保留 2D 功能）；开发态可选上报 console。
- **已落地（2026-11）**：独立脚本块安装全局错误兜底——`error`（过滤无 message 的资源加载事件）+ `unhandledrejection` 双钩子，console.error 保留原始堆栈，玻璃错误 toast 上报，3 秒限频防错误风暴。
- **关键路径降级已落地（2026-11）**：`init3DViewport` 包裹 try-catch + THREE/WebGL 可用性前置检测；失败时 `degrade3DViewport` 隐藏 PiP、置 `pip3dAvailable=false` 短路全部后续 3D 调用（`build3DBoxStructure` / `highlightFace` 的 3D 段 / `toggleSplitView`），warning toast 告知 2D 工作台完整可用。修复了降级前 init 异常会中断 load 链（连持久化初始化一并丢失）的问题。已用 THREE 访问器 stub 模拟 CDN 失败实证：PiP 隐藏、init 链（含持久化）完整执行。

### 2.4 无撤销/重做 🟠 P1 →【已实现（2026-11）】
- **现状**：印前修复开关（RGB 转色/直压/TAC/转曲/除墨）各按钮自带"再点一次撤销"的双态逻辑，但删除卡尺测线、重置缺陷样张、导入覆盖等操作不可逆。
- **方案**：对 state 白名单字段实现命令栈（快照式，限深 30 步），Ctrl+Z / Ctrl+Shift+Z 接入；破坏性操作（Delete 卡尺线、导入覆盖）入栈。
- **已落地**：`PrintGuardStore.createUndoStack` 快照式栈（限深 30、批合并 900ms、新操作分叉清空重做分支）；`createStateProxy` 新增赋值前 before 快照回调，撤销快照剔除附件/资产域（dataURL、DXF 原文、资产名——撤销只回滚参数状态，不回滚资产，内存取舍）；`applySnapshot` 回放期抑制入栈，外部加载（恢复横幅/载入工程/导入工程文件）作为撤销断点重置栈。Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y 已接入快捷键系统与键位表。附带修复：图层开关就地变异导致浅层 Proxy 捕获不到（自动保存脏标记漏标）——改为整体替换。

### 2.5 样式零组件化 / 设计系统缺失 🟠 P1 →【本次以设计系统层缓解】
- **现状**：无 CSS 自定义属性体系，颜色令牌只存在于 Tailwind config；同一卡片类串重复 15 次；61 处 JS 硬编码 className；dock/drawer 三态用 20+ 个 `!important` 压优先级。
- **影响**：换肤/改版成本极高，且已在发生：`from-[#090e1d]` 等色值绕过令牌直接漂移，证书模态自成一套灰阶。
- **方案**：本次落地 `css/design-system.css`——CSS 变量设计令牌 + 玻璃组件类（.glass-card/.glass-btn/.glass-input 等），新代码一律用组件类；存量 Tailwind 工具类通过重定义 config 令牌整体换肤。路线图：逐步把 15 处复制卡片串替换为 .glass-card，删除 !important 堆积。

### 2.6 可访问性与触屏近乎为零 🟡 P2 →【路线图】
- **现状**：全文 2 个 aria-label，0 个 role/tabindex/alt；模态框无焦点陷阱、无焦点归还；字号大量 text-[9px]/[10px]；主画布仅鼠标事件（仅 PiP 拖动有 touch 处理）；`body` 全局 select-none。
- **方案**：模态框 role="dialog" + Esc 关闭已有但补焦点管理；dock/面板按钮加 aria-label；画布补 pointer events 统一指针（鼠标/触摸/笔）；提供 ARIA live region 供快捷键播报。

### 2.7 重像素运算在主线程 🟡 P2 →【路线图】
- **现状**：`industrialCmykPixel()` 分色流水线、`InkZoneEstimator.analyzeInkZones`（getImageData 全画布取样）、32 墨区柱状图渲染均在主线程同步执行。
- **影响**：大尺寸设计稿导入后首次分色/出报告时可感知卡顿。
- **方案**：把 ciede2000 模块与墨区分析包装进 Web Worker（模块已是纯函数 UMD，天然可迁移），主线程仅收结果；或 OffscreenCanvas。

## 3. 架构演化路线图（建议顺序）

1. **P0** 持久化（本次 ✅）——先让"工作"能留下来
2. **P0** 离线化：vendor 本地依赖 → 告别 Play CDN → PWA
3. **P1** 全局错误防护 + 关键路径降级
4. **P1** 撤销/重做命令栈
5. **P1** 样式迁移收尾：存量工具类逐步收敛到 design-system 组件类，删除 !important 堆积；拆分 index.html 内联脚本为 `js/app-*.js`（延续现有 UMD 风格，保持零构建）
6. **P2** 可访问性 + 触屏 pointer events
7. **P2** Web Worker 化重像素运算
8. **P3** 若需多人协作/报价单据流转：以 `.printguard` 工程文件为交换格式引入后端（建议 SQLite + 文件服务），前端已具备序列化层可直接复用

## 4. 值得保留的优点（重绘/重构时不得破坏）

- 6 引擎模块的双端 UMD 设计与自测套件——任何 UI 改动后跑 `node module_*.js` 即可回归
- 工业语义完整性：BWR 补偿、CITO 压痕、UCR/GCR 控墨、GS1 静区等术语与算法准确
- 画布交互体系（毫米标尺/卡尺/显微镜/密度计 HUD/缺陷声呐）是产品核心价值，重绘只换皮肤不动坐标与事件数学
- 零构建哲学：保持双击可跑，避免引入 npm/打包链
